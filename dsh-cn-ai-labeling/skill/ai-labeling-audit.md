面向中国大陆市场的产品，在**设计、开发、发版前**逐条核对 AI 生成合成内容标识是否落实。

## 一、第 0 步：先确定「你是不是义务主体」

**跳过这一步直接查功能，会得出错误结论。** 这套规则约束的是**服务提供者**，不是产品形态。

### 1.1 三种形态，义务归属完全不同

| 形态 | 谁是生成合成服务提供者 | 你要做什么 |
|---|---|---|
| **A. 你自建 AI 服务面向公众**（用户连你的服务器、用你的模型额度/接口） | **你** | 全部条款适用。显式 + 隐式标识、协议、上架材料都要做 |
| **B. 你只做客户端 / 工具**，用户自部署、自配模型 | **用户**（或模型厂商） | 标识义务不在你。但你必须**提供标识能力**并说明义务归属，见 1.4 |
| **C. 端上跑本地模型** | **你**（端本身就是提供者） | 同 A |

### 1.2 判定主体的原文依据

- 《深度合成规定》第二十三条：**深度合成服务提供者**，是指提供深度合成服务的组织、个人。
- GB 45438 3.7：利用人工智能技术（**包括通过提供可编程接口等方式**）向公众提供生成合成……服务的组织或个人。
- 《标识办法》第二条：适用主体是**符合**《算法推荐管理规定》《深度合成规定》《生成式人工智能服务管理暂行办法》**规定情形**的网络信息服务提供者。

**要点**：「通过提供可编程接口」被明确写进定义——**套壳调第三方 API 不豁免**，只要是你面向公众提供了生成服务，你就是提供者。

### 1.3 划清「深度合成技术」的边界

《深度合成规定》第二十三条列举了 6 类技术，包括篇章生成/文本风格转换/问答对话、文本转语音/语音转换、音乐生成、人脸生成替换编辑、图像生成增强修复、三维重建/数字仿真。

**只是把一个文件转格式、压缩、切分，不属于深度合成**——不要给这类功能扣标识义务。

### 1.4 形态 B（工具方）仍然要做的三件事

法律上你不是义务主体，但下面的现实风险由你承担：

1. **提供标识能力**。用户的产出要合规，而**导出链路只有你能改**——《标识办法》第四条第二款要求"提供下载、复制、导出等功能时，应当确保文件中含有满足要求的显式标识"。用户自己补不了元数据。
2. **在用户协议 / 帮助文档里说明标识方法**，并提示用户其自身义务（对应《标识办法》第八条的思路）。用户是义务主体，协议里说清楚对双方都是保护。
3. **上架时如实回答**（见第五节 D1）。

> 判定为形态 B 时，**不要输出「你未做标识，违反 GB 45438」这类结论**。正确结论是：「标识义务在用户侧；你的导出链路是用户可以合规的前提，建议实现。」

## 二、义务面：显式标识窄，隐式标识宽

**这是最容易搞错、也最容易过度合规的一点。**

| | 法条链 | 适用面 |
|---|---|---|
| **隐式标识** | 深度合成规定第十六条 → 标识办法第五条 → GB 45438 6.1 | **宽**：深度合成服务提供者**对使用其服务生成或者编辑的信息内容**，都应当采取技术措施添加标识 |
| **显式标识** | 深度合成规定第十七条第一款 → 标识办法第四条 | **窄**：仅限**可能导致公众混淆或者误认**的 5 类服务 |
| **显式标识功能（兜底）** | 深度合成规定第十七条第二款 | 第十七条第一款**之外**的深度合成服务：应当**提供标识功能**，并提示使用者可以标识 |

### 2.1 第十七条第一款的 5 类（显式标识的强制触发条件）

1. 智能对话、智能写作等模拟自然人进行文本的生成或者编辑服务
2. 合成人声、仿声等语音生成或者显著改变个人身份特征的编辑服务
3. 人脸生成、人脸替换、人脸操控、姿态操控等人物图像、视频生成或者显著改变个人身份特征的编辑服务
4. 沉浸式拟真场景等生成或者编辑服务
5. 其他具有生成或者显著改变信息内容功能的服务

> GB 45438 附录 B 给了更细的 9 条应用场景（多了文生图片、音乐创作、文生视频/图生视频），**附录 B 是资料性**——它是判定参考，不是独立义务来源。判定仍以第十七条第一款为准。

### 2.2 这个宽窄差意味着什么

- 一个只做**图片生成**的产品：显式标识要看是否落入第十七条第一款；**隐式标识（文件元数据）从第十六条起就是普遍要求**。
- 一个**不落入第一款**的深度合成功能：不是"不用标识"，而是"**要提供标识功能并提示用户**"。

## 三、自检清单 A：显式标识

### A0. 触发前提

- [ ] 该功能是否落入《深度合成规定》第十七条第一款 5 类之一？
- [ ] 若否 → 走 2.2 的兜底路径（提供标识功能 + 提示用户），**不必**套用下面的介质细则。

### A1. 所有介质共同要求（GB 45438 5.1 b / 5.2 b / 5.3 b / 5.4 b / 5.5 b / 5.6 b）

标识文字**必须同时包含**两个要素：

- [ ] **人工智能要素**：含「人工智能」或「AI」
- [ ] **生成合成要素**：含「生成」和/或「合成」

> 唯一例外：**文本的角标形式只需含「AI」**（GB 45438 5.1 c）。

### A2. 文本（GB 45438 5.1）

- [ ] 形式：文字 或 角标
- [ ] 位置：位于**文本的起始位置 / 末尾位置 / 中间适当位置**之一或多个
- [ ] 字型和颜色清晰可辨
- [ ] 文字形式含「人工智能|AI」+「生成|合成」；角标形式含「AI」

### A3. 图片（GB 45438 5.2）

- [ ] 形式：文字提示
- [ ] 位置：位于**图片的边或角**
- [ ] 字型清晰可辨
- [ ] **文字高度 ≥ 画面最短边长度的 5%**
- [ ] 非矩形图片按「能完全包含该图片的矩形」的最短边计算

### A4. 音频（GB 45438 5.3）

- [ ] 形式：**语音标识** 或 **音频节奏标识**
- [ ] 节奏标识为「**短长 短短**」（AI 的摩斯码）
- [ ] 位置：音频的起始 / 末尾 / 中间适当位置之一或多个
- [ ] 「起始」在音频内容**开始之前**，「末尾」在内容**结束之后**（不是叠在内容上）
- [ ] 智能语音助手 / 智能客服 / 智能导航等高频交互场景：「起始/末尾」指**一轮交互**的起止
- [ ] 语音标识使用正常语速（汉语约 120～160 字/min）
- [ ] 节奏标识清晰可辨

### A5. 视频（GB 45438 5.4）

- [ ] 形式：文字提示
- [ ] **应位于视频起始画面**（强制）；**可**位于末尾和中间适当位置
- [ ] 位于视频画面的边或角
- [ ] 字型清晰可辨
- [ ] **文字高度 ≥ 画面最短边长度的 5%**
- [ ] **正常播放速度下持续时间 ≥ 2s**

### A6. 虚拟场景（GB 45438 5.5）

- [ ] 形式：文字提示
- [ ] **应位于虚拟场景起始画面**；可位于持续服务过程中的适当位置
- [ ] 起始画面的标识位于画面的边或角
- [ ] 字型清晰可辨
- [ ] **文字高度 ≥ 画面最短边长度的 5%**

### A7. 交互场景界面（GB 45438 5.6）

- [ ] 形式：文字提示（含两要素）
- [ ] 方式（一种或多种）：
  - [ ] 在内容附近**持续显示**提示文字
  - [ ] 在界面**顶部 / 底部 / 背景**等适当位置**持续显示**提示文字
- [ ] 字型和颜色清晰可辨

> 「**持续显示**」是关键——只在生成那一刻闪一下、或需要悬停才出现，不满足。

### A8. 下载 / 复制 / 导出链路（《标识办法》第四条第二款）

- [ ] 提供下载、复制、导出功能时，**确保文件中含有满足要求的显式标识**
- [ ] 逐条核对每条导出路径（Word / Excel / PPT / PDF / 图片 / 音视频），不是只改一条

## 四、自检清单 B：隐式标识

### B1. 五要素齐备（GB 45438 6.1 a）

文件元数据隐式标识应包括：

- [ ] **生成合成标签要素**：内容的人工智能生成合成属性信息
- [ ] **生成合成服务提供者要素**：生成合成服务提供者的名称或编码
- [ ] **内容制作编号要素**：生成合成服务提供者对该内容的唯一编号
- [ ] **内容传播服务提供者要素**：内容传播服务提供者的名称或编码
- [ ] **内容传播编号要素**：内容传播服务提供者对该内容的唯一编号

（另有 `ReservedCode1` / `ReservedCode2` 两个预留字段，见附录 E）

### B2. 格式必须符合附录 E（**规范性**，不是示例）

- [ ] 字段名称或关键词中**包含「AIGC」**
- [ ] 值为如下格式的**字符串**：

```json
{"AIGC":{"Label":"value1","ContentProducer":"value2","ProduceID":"value3",
         "ReservedCode1":"value4","ContentPropagator":"value5",
         "PropagateID":"value6","ReservedCode2":"value7"}}
```

- [ ] `Label` 取值：**`1` = 属于**人工智能生成合成 / **`2` = 可能为** / **`3` = 疑似为**
- [ ] 所有要素**类型均为字符串**（`Label` 也是字符串 `"1"`，不是数字 `1`）
- [ ] 首次写入时（附录 E 注 1）：`ContentPropagator` 与 `ContentProducer` 一致、`PropagateID` 与 `ProduceID` 一致
- [ ] 各要素的值**主要由 GB 18030—2022 中码位 `0x21`、`0x23~0x5B`、`0x5D~0x7E` 的字符以及 `\"` 构成**（即：可打印 ASCII，排除双引号与反斜杠，双引号用 `\"` 转义）

### B3. 唯一性（GB 45438 6.1 c）

- [ ] **同一文件中应仅保留一份文件元数据隐式标识**

> 反复导出 / 复制 / 转发时，是**覆盖**旧标识，不是**追加**。这条在实现上意味着写入前要先清除已有的 AIGC 块。

### B4. 落点

- [ ] 图片：XMP 的 `AIGC` 字段（附录 F.1 示例）
- [ ] 音频 / 视频：容器级元数据（附录 F.2 / F.3 示例）
- [ ] 允许用杂凑算法做数字签名放进 `ReservedCode1` 防篡改（附录 F.4 示例，资料性）

## 五、自检清单 C / D：协议、分发、备案

### C1. 用户服务协议（《标识办法》第八条）

- [ ] 在用户服务协议中**明确说明生成合成内容标识的方法、样式等规范内容**
- [ ] 提示用户仔细阅读并理解标识管理要求

### C2. 无显式标识版本（《标识办法》第九条）

- [ ] 若提供"不带显式标识"的生成结果：已通过用户协议明确**用户的标识义务和使用责任**
- [ ] **依法留存提供对象信息等相关日志不少于六个月**

### C3. 禁止性要求（《标识办法》第十条第二款）

- [ ] 产品不提供任何**删除 / 篡改 / 伪造 / 隐匿**标识的功能
- [ ] 不提供绕过标识的"清洗"能力
- [ ] 对应《深度合成规定》第十八条：不得采用技术手段删除、篡改、隐匿标识

### D1. 应用分发平台上架（《标识办法》第七条）

- [ ] 上架时准备好"**是否提供人工智能生成合成服务**"的说明
- [ ] 若答"是"，备好**生成合成内容标识相关材料**供平台核验
- [ ] 另见《深度合成规定》第十三条：分发平台会核验深度合成类应用的**安全评估、备案**情况

### D2. 备案与安全评估（《标识办法》第十二条）

- [ ] 履行算法备案、安全评估等手续时，按本办法提供**生成合成内容标识相关材料**
- [ ] 参考《深度合成规定》第十九条（具有舆论属性或社会动员能力的备案要求）、第二十条（新功能上线安全评估）

## 六、明确「不构成强制要求」的项 —— 防止误伤

**误报多了，人就再也不看报告了。** 以下都是常见误判，逐条列明：

| 常见误判 | 事实 | 依据 |
|---|---|---|
| 「附录 A/B/C/D/F 没做」 | 这 5 个附录都是**资料性**（推荐、示例），**只有附录 E 是规范性** | GB 45438 各附录标题 |
| 「没加数字水印，违规」 | 数字水印是**准许采用 / 鼓励**，**不做要求** | GB 45438 6.2；附录 A.2 明确「在本文件中不做要求」；标识办法第五条为「鼓励」 |
| 「文本角标没写『生成』」 | **文本角标形式只需含「AI」**，不要求生成合成要素 | GB 45438 5.1 c |
| 「文本 / 音频 / 界面标识字号不达标」 | **5% 字高只适用于图片、视频、虚拟场景** | GB 45438 5.2 e / 5.4 f / 5.5 f |
| 「视频末尾没标」 | 视频**只有起始画面是「应」**，末尾和中间是「可」 | GB 45438 5.4 c |
| 「虚拟场景服务过程中没标」 | 只有**起始画面是「应」** | GB 45438 5.5 c |
| 「图片标识没有持续时长」 | 图片**没有时长要求**；2s 只针对视频 | GB 45438 5.4 g |
| 「所有 AI 功能都要加显式标识」 | 显式标识仅对《深度合成规定》**第十七条第一款**情形强制 | 标识办法第四条 |
| 「把人工撰写的内容也打上 AI 生成标」 | 标识**只用于 AI 生成合成内容**；给非 AI 内容加标识是**反向错误** | GB 45438 3.1 / 3.2 |
| 「文件格式转换 / 压缩 / 切分要标识」 | 不属于深度合成技术 | 深度合成规定第二十三条 |
| 「工具方没做标识，违规」 | 义务主体是服务提供者；工具方义务见 1.4 | 标识办法第二条 |

## 七、机械取证

脚本随本插件分发，技能正文会给出它的**绝对路径**：

```bash
# 1) 扫代码库，收集"标识实现"的证据与缺口
bash <labeling-check.sh 路径> --code --dir .

# 2) 校验一个真实产出文件的元数据（导出物 / 图片 / 文档）
bash <labeling-check.sh 路径> --meta ./导出样例.docx
bash <labeling-check.sh 路径> --meta ./生成图.png

# 3) 一次全跑
bash <labeling-check.sh 路径> --all --dir .
```

脚本只做**取证**，不做定性——它报告"找到了什么、缺什么"，是否违规由人判断。

**退出码**：`0` = 未发现问题；`1` = 有发现 —— 可直接用作 CI / 发版前卡口。

## 九、需人工判断、脚本查不出的项

- 「可能导致公众混淆或者误认」的实质判断（第十七条第一款的适用性）
- 「适当位置」「合理位置」的合理性
- 「清晰可辨」的实际视觉效果——需真机 / 实际渲染确认
- 「持续显示」是否真的持续（需交互验证，静态代码看不出）
- 主体形态归属（形态 A / B / C）——取决于你的商业模式，不是代码特征
- 是否已触发算法备案 / 安全评估义务
