# @deepwhale-cn/dsh-cn-appstore-preflight

**国内应用市场上架预检** —— 给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 用的 skill 插件。

在**提交应用市场之前**做一次体检：从上架材料的角度，把会被驳回的地方先找出来。

## 它查什么

| 项 | 具体是什么 |
|---|---|
| **App 备案** | 备案号是否在 App 内可查；**网站 ICP 备案 ≠ App 备案**（最常见的一处填错） |
| **隐私政策** | 链接是否可达、能否从 App 内打开 |
| **权限** | 清单是否最小必要；有没有准备「使用场景说明」 |
| **账号注销** | 是否有用户可**自助完成**的入口（多数市场不接受发邮件申请） |
| **未成年人保护** | 是否有相应机制（按产品形态判断是否适用） |
| **上架材料** | 包名/版本/targetSdk/软著/第三方 SDK 清单 —— 生成骨架，照着往后台填 |

## 它给的是骨架，不是某家市场的官方清单

各应用市场（华为 / 小米 / OPPO / vivo / 应用宝 / 鸿蒙）的要求**不同且会变**。
本技能与它带的脚本都明确写着：**以目标市场的官方最新公告为准**。

编一条"看起来很像"的规定比不写更糟糕 —— 用户会照着它准备材料，然后在提交时被打回。

## 与相邻技能的分工

这四个包是**刻意分开**的，本技能**不重复**别人的活：

| 包 | 管什么 |
| --- | --- |
| **`dsh-cn-appstore-preflight`** | **材料齐不齐、上架能不能过** |
| `dsh-cn-pipl-check` | 隐私**声明与实现**是否一致 |
| `dsh-cn-compliance` | 对外**文案**红线 |
| `dsh-cn-ai-labeling` | AI 生成内容的**标识** |
| `dsh-release-selfcheck` | 发布产物与流程 |

## 安装

```bash
dsh plugin --profile <profile> add @deepwhale-cn/dsh-cn-appstore-preflight
```

然后重启 dsh。技能会在需要时自动可用。

## 用法

```bash
# 脚本路径由插件注册时注入到技能正文里，或到安装目录找 skill/scan.sh
scan.sh --dir /path/to/app
```

输出分两段：**取证**（包名、备案号、隐私政策入口、权限、注销入口、未成年人）
＋ **上架材料清单骨架**（可直接照着填市场后台）。

## 典型驳回原因（脚本会帮你先看一遍）

1. 隐私政策不可达，或与实现不一致
2. 无账号注销入口
3. 权限与功能无关，或一启动就申请
4. App 备案缺失，或填了网站的 ICP 备案
5. 截图/描述文案踩红线
6. 第三方 SDK 未在材料里披露
7. 版本号未递增或与后台填写不一致

> 本技能是一份准备清单，**不构成法律意见**。
