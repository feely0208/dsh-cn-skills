# @deepwhale-cn/dsh-cn-compliance

**中国大陆对外内容合规红线审核** —— 给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 用的 skill 插件。

在内容**发布之前**主动查出合规风险，避免备案被卡、页面被下架、行政处罚。

## 它查什么

| 类别 | 内容 |
|---|---|
| 🔴 **A 类** | 网络工具用语（`VPN` / `翻墙` / `科学上网` / `机场` / `clash` …）—— 绝对红线 |
| 🔴 **A- 类** | 擦边词（`内网穿透` / `隧道`）—— **需语境判断**，见下 |
| 🔴 **B 类** | 广告法极限用语（`国家级` / `唯一` / `独家` / `最好` / `首个` …） |
| 🟠 **C 类** | 绝对化承诺（`永久免费` / `零风险` / `绝不泄露`） |
| 🟠 **D 类** | 地图与领土（台湾、藏南、南海诸岛完整性） |
| 🟠 **E 类** | 数据与隐私承诺（隐私政策必须与实现一致） |
| 🟠 **F 类** | AI 生成内容标识 |
| 🟡 **G 类** | 资质与备案（ICP 备案号、不得宣称没有的资质） |
| 🟡 **H 类** | 比较与贬低竞争对手 |
| 🔴 **I 类** | **内部文件公网暴露**（信息安全 + 合规双风险） |

## 安装

```bash
dsh plugin --profile <profile> add @deepwhale-cn/dsh-cn-compliance
```

然后重启 dsh。技能会在 agent 需要时自动可用。

## 为什么它比"列一堆敏感词"有用

敏感词表谁都能列。**难点在误报**——一次全量扫描出几百条噪音，人就不看报告了，等于没审。

本插件内置了两条**语境判断**，这是它可用与否的分水岭：

| 词 | 误报场景 | 处理 |
|---|---|---|
| `穿透` `隧道` | UI 术语「点击穿透」、HTTP tunnel | **只在网络语境同现时**才判风险（内网/网络/端口/代理/路由/NAT） |
| `100%` | CSS 的 `0%,100%` 关键帧、`width:100%` | **只在后接营销形容词时**才报（`100%自研/安全/有效…`） |

同时排除已知的噪音源：`node_modules/`、随包运行时目录（内含几百个第三方 README）、
构建产物、二进制、第三方抓取的新闻内容。

## 扫描脚本

插件随包分发 `scan.sh`，技能正文里会给出它的**绝对路径**。

```bash
# 扫当前目录
bash <scan.sh 路径>

# 扫指定目录
bash <scan.sh 路径> --dir ./site

# 公开仓库：只扫 .md，避开源码里的技术术语误报
bash <scan.sh 路径> --docs-only

# 扫线上页面（最重要 —— 本地干净 ≠ 线上干净）
SITE_HOST=https://your-domain.example bash <scan.sh 路径> --online

# 本地 + 额外文档 + 线上 + 内部路径暴露探测
SITE_HOST=https://your-domain.example DOCS_DIRS="./docs:./README.md" bash <scan.sh 路径> --all
```

**退出码**：`0` = 无命中；`1` = 有命中 —— 可直接用在 CI / 发布前卡口。

## 环境变量

| 变量 | 说明 |
|---|---|
| `SITE_HOST` | 线上站点根地址（`--online` / `--all` 必需） |
| `DOCS_DIRS` | 额外要扫的文档目录，冒号分隔 |
| `EXTRA_PATHS` | 额外要探测的内部路径，空格分隔（追加到内置清单） |

## 设计取舍

**不内置政治敏感词表。** 一是避免插件文件本身含敏感内容，二是这类词表需要持续
跟踪监管口径，不适合固化在插件里。C 类请人工审核或使用第三方工具。

**不联网获取词表。** 只做本地与指定站点的检查，不把待审内容发往任何第三方服务。

## 与其它插件的关系

本插件只管**话** —— 对外文案里不能说什么。要逐条核对**产品实现**里 AI 生成内容标识
有没有做进代码与导出物，用 [`@deepwhale-cn/dsh-cn-ai-labeling`](https://www.npmjs.com/package/@deepwhale-cn/dsh-cn-ai-labeling)。

按 [DSH 插件生态倡议书](https://github.com/anywhere-labs/dsh-desktop/blob/main/docs/plugin-ecosystem.md)
的三条原则开发：**组合优先、声明清晰、兼容优先**。不假设、不覆盖其它插件的内部实现。
