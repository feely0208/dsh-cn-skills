# 对外内容合规红线审核

**目的**：在内容发布**之前**主动查出中国大陆合规风险，避免备案被卡、页面被下架、行政处罚。

**适用对象**：面向中国大陆用户的官网、GitHub 公开文档与 README、App 内用户可见文案、
公众号推文、宣传物料（海报 / 名片 / PPT）。

**不适用**：内部交接文档、会话记录（这些不对外，可以写）。

---

## 一、何时必须审

满足任意一条就要跑一遍审核，**不要等用户提**：

- 改完官网任意页面，**部署前后各一次**
- 新增 / 修改产品文案、下载页说明、使用指南
- 写 GitHub 上的公开文档（README、docs/、release notes）
- 写公众号推文、宣传物料文案
- App 内的用户可见文案（尤其权限说明、隐私相关）
- 用户说「合规」「敏感」「红线」「审核一下」

---

## 二、先跑扫描脚本

本 skill 自带 `scan.sh`（路径见文末「相关文件」）。

```bash
bash <scan.sh 路径>                 # 默认扫当前目录
bash <scan.sh 路径> --dir <路径>    # 指定目录
bash <scan.sh 路径> --online        # 抓线上页面（**最重要**）
bash <scan.sh 路径> --all           # 本地 + 线上 + 内部路径暴露探测
```

**⚠️ 本地干净 ≠ 线上干净。** 必须跑 `--online`，因为：

- 可能漏部署
- 可能有缓存版本不一致
- 线上才是用户真正看到的

线上扫描前需要设置 `SITE_HOST` 环境变量：

```bash
SITE_HOST="https://your-domain.example" bash <scan.sh 路径> --online
```

## 三、敏感项分类（**这是本 skill 的核心**）

### 🔴 A 类：网络工具类（**最严重**）

| 级别 | 词 |
|---|---|
| **绝对禁用** | `VPN`、`vpn`、`虚拟局域网`、`虚拟专用网络`、`翻墙`、`科学上网`、`梯子`、`机场`、`加速器`、`shadowsocks`、`v2ray`、`clash`、`trojan` |
| **建议一并避免** | `内网穿透`、`穿透`、`隧道`、`tunnel`、`代理工具`、`绕过`、`突破封锁` |

**判断标准**：

> **只描述「要实现什么」，不点名「用什么技术」。**

- ✅ 「你需要自行解决网络可达性」「让手机能够跨网络访问」
- ❌ 「你可以用 VPN / 内网穿透 / 隧道」

### 🔴 B 类：广告法极限用语（**处罚高发区**）

《广告法》第九条禁止使用「国家级」「最高级」「最佳」等用语。
含下列字样**必须改成可证明的具体表述**：

| 类别 | 词 |
|---|---|
| 极限 | `最`（最好/最强/最快/最优/最大/最小/最便宜）、`第一`、`首个`、`首家`、`首创` |
| 权威 | `国家级`、`世界级`、`国际级`、`国家认定`、`官方指定`、`央视上榜` |
| 绝对 | `唯一`、`独家`、`顶级`、`极致`、`王牌`、`冠军`、`领先`、`领先的` |
| 满分 | `100%`、`全网最低`、`全球第一`、`绝对`、`万能` |

**需人工判断（不是必然违规，但要看是否有依据）**：

- `永久免费`、`终身`、`保证`、`零风险`、`绝不`、`永远`
  → 若是**可兑现的事实承诺**（如开源协议决定的「永久免费」）风险较低；
  → 若属**效果承诺**（如「绝不泄露」「零风险」）则高风险，必须改。

### 🔴 C 类：政治敏感 / 时政

**本 skill 不内置政治敏感词表**（避免 skill 文件本身含敏感内容）。审核方式：

- 商业内容中**不得涉及**国家领导人、政治事件、涉港涉台涉藏等议题
- 用第三方敏感词检测工具过一遍，或**人工审**
- 公众号发文前尤其要审（平台侧有自动审核）

### 🟠 D 类：地图与领土（**高频雷区**）

- 任何中国地图**必须完整**：含台湾、藏南、南海诸岛及九段线
- 不得把台湾与中国并列、不得使用错误称谓
- 地图类素材（宣传物料、App 内）**发布前必须放大逐个检查**
- 用官方标准地图：自然资源部标准地图服务

### 🟠 E 类：数据与隐私承诺

- 禁止绝对化承诺：`绝对安全`、`零风险`、`绝不泄露`、`100% 保护`
- **隐私政策必须与实际行为一致**（写「不收集」就必须真的不收集）
- 声明「数据只在你的设备上」时，要确保**调用 AI 时的数据流向描述准确**——
  准确说法：内容保存在你自己的设备；调用 AI 时发往你自行配置的模型服务；
  我们不中转、不缓存、不留存

### 🟠 F 类：AI 生成内容

- 不得宣称 AI 输出可替代专业判断（医疗、法律、金融场景尤其敏感）
- 应明确「AI 生成内容仅供参考，需人工核验」
- 《生成式人工智能服务管理暂行办法》要求对 AI 生成内容作标识

### 🟡 G 类：资质与备案

- **ICP 备案号**必须展示（页脚），且链接到 `beian.miit.gov.cn`
- 公安联网备案号（批准后）也应展示
- **不得宣称没有的资质**：`国家认证`、`官方合作`、`XX 协会指定`
- 不得宣称与政府 / 司法机关有合作关系，除非确有书面依据

### 🟡 H 类：比较与贬低

- 不得贬低竞争对手（指名或暗示）
- 不得未经授权使用他人商标、产品截图、logo 做对比

### 🔴 I 类：内部文件公网暴露（信息安全 + 合规双风险）

**典型事故**：把服务器内部脚本目录（部署时顺手上传）留在网站根目录下，
被 nginx 当静态文件对外服务，导致脚本源码、内部文档全部公网可读。
更糟的是，**内部文档里往往写着不适合公开的内容**（内部地址、术语、注释），
于是同时踩两条线：

→ **信息安全**（暴露服务器路径与机制）+ **合规**（公开页面出现禁用词）。

**为什么容易漏**：那个目录是服务器自己要用的（例如定时任务脚本），
部署时顺手一起同步上去了，但**没人意识到 Web 服务器会把它当静态资源对外提供**。

**必须屏蔽的路径**（`scan.sh --all` 会逐条探测是否可公网访问）：

| 路径 | 说明 |
|---|---|
| `/.git/` | 版本库（泄露源码与提交历史） |
| `/.env` | 环境变量与密钥 |
| `/package.json`、`/docker-compose.yml` | 依赖与部署信息 |
| `/backup.zip` 等备份文件 | 常见遗留 |
| 任何内部脚本 / 文档目录 | 按你的项目实际情况补充 |

**nginx 屏蔽写法**（放在 HTTPS server 块内）：

```nginx
# return 404 而非 403 —— 不暴露「这里存在东西」
location ^~ /.git/ { return 404; }
location ~* /(package\.json|docker-compose\.yml|\.env.*)$ { return 404; }
```

> `^~` 前缀匹配优先级高于正则，能压住 `location ~* \.(js|css|...)$` 那条缓存规则。
> **改完必须测**：`curl -sI https://你的域名/.git/config` 应回 404。

## 三·补：怎么判断误报（调优经验）

**误报会让脚本没法用**（一次全量扫描可能出几百条噪音）。以下是要点：

### 必须排除的扫描对象

| 对象 | 原因 |
|---|---|
| `node_modules/` `vendor/` `third_party/` | 第三方代码 |
| 随包运行时目录（如 `*-runtime/`） | ⚠️ 里面几百个 npm 包的 README，一开扫就是 300+ 条噪音 |
| `release/` `dist/` `build/` | 构建产物 |
| `*.png/jpg/dmg/exe/apk/zip/asar` | 二进制 |
| 第三方抓取的内容文件（如 `news.json`） | ⚠️ 其用词（新闻里的「最快/独家」）不代表你的表述 |
| **源码目录（`src/`）** | ⚠️ 技术术语会造成大量误报（如 CSS 的 `pet-clickthrough` = 「**穿透**点击」）<br>→ 仓库只扫 `*.md` |

### 需要「语境判断」的词

| 词 | 误报场景 | 处理 |
|---|---|---|
| `100%` | CSS 的 `0%,100%` 关键帧、`width:100%` | 只在后接**营销形容词**时才报（`100%自研/安全/有效…`） |
| `穿透` `隧道` | UI 术语「点击穿透」；HTTP tunnel | 只在**与网络词同现**时才报（内网/网络/端口/代理/路由/NAT） |

### 关键原则

> **宁可漏报也不误报**——误报多了，人就不看报告了，等于没审。

### 净化后应达到

- 扫描结果**逐条可判断**，不需要人工过滤噪音
- 每条命中都**给出上下文**，便于直接定位

## 四、审核流程

1. **本地扫描** → 修掉确定的违规
2. **人工看命中项** → 区分「必须改」和「语境误报」
3. **部署**
4. **线上扫描**（`--online`）→ 确认改的生效了、没有遗漏
5. **内部路径探测** → 确认没有不该公开的目录
6. **出报告**

### 线上复查（必做）

```bash
SITE_HOST="https://你的域名" bash <scan.sh 路径> --online
```

**⚠️ 本地 grep 不算数**——线上才是用户看到的。

## 六、修复原则

| 原则 | 说明 |
|---|---|
| **改成可证明的表述** | 「最专业」→「由 X 名执业律师提供服务」 |
| **删除比辩解安全** | 拿不准就删 |
| **不要换个说法继续踩** | 「最」换成「极」同样是极限词 |
| **隐私承诺必须与实现一致** | 写不收集就必须真的不收集；做不到就改措辞 |
| **改完必须跑线上复查** | 本地改了不等于线上生效 |
